# Xiaomi Mi Notebook Air 13.3-inch (TM1703)

This page describes the coreboot port for the 2018 Xiaomi Mi Notebook Air
13.3-inch, board model Compal TM1703.

## Technology

```{eval-rst}
+------------------+------------------------------------------------------+
| CPU              | Intel Core i5-8250U / Core i7-8550U (Kaby Lake-R)    |
+------------------+------------------------------------------------------+
| PCH              | Intel Sunrise Point-LP                               |
+------------------+------------------------------------------------------+
| Integrated GPU   | Intel UHD Graphics 620 (8086:5917)                   |
+------------------+------------------------------------------------------+
| Discrete GPU     | NVIDIA GeForce MX150, GP108M (10de:1d12) or None     |
+------------------+------------------------------------------------------+
| Memory           | Soldered DDR4 (8 GiB / 16 GiB), selected by straps   |
+------------------+------------------------------------------------------+
| EC               | Nuvoton NPCE family (firmware in shared SPI flash)   |
+------------------+------------------------------------------------------+
| Coprocessor      | Intel CSME 11.8                                      |
+------------------+------------------------------------------------------+
| SPI flash        | Winbond W25Q128.V, 16 MiB, SOIC-8                    |
+------------------+------------------------------------------------------+
```

The board has no SO-DIMM socket. Different memory-down configurations are
selected using the `GPP_D0..D3` straps, and their SPD data is stored in CBFS.

## Status

### Working

- Booting and running Linux operating systems
- FSP-M memory initialization with tested soldered DDR4 configurations
- Native coreboot multiprocessor initialization on all CPU threads (SMP)
- Intel UHD 620 display initialization with native libgfxinit (linear framebuffer)
- Internal eDP display and built-in keyboard
- Touchpad (I2C HID on I2C1; I2C0 enabled for PCI slot 15 topology)
- EC event handling: Fn hotkeys, fan control, lid switch, battery status, and ACPI power button
- USB-C Power Delivery and UCSI functionality
- Enumeration and ACPI `_ROM` method delivery for NVIDIA GeForce MX150 (`10de:1d12`)
- PCIe peripherals: Intel Wireless-AC 8265 and NVMe SSD
- Intel CSME initialization (including DRAM Init Done and End of Post)
- SPI flash console for early boot diagnostics
- S3 suspend and resume (Suspend-to-RAM)
- CMOS option table and runtime configuration via nvramtool (USE_OPTION_TABLE)
- Internal audio (Realtek ALC255), stereo speakers, and digital microphone
- External HDMI and USB-C DisplayPort Alternate Mode video output and digital audio
- USB webcam (Foxlink XiaoMi USB 2.0 Webcam) and USB fingerprint reader (ELAN)

### Not working

- Internal firmware flashing with flashrom (not supported at this stage)

### Untested / Work in progress

- Additional Intel Serial IO I2C controllers (I2C2..I2C5)
- Runtime D3cold power management (RTD3) of the NVIDIA GPU

## Required proprietary blobs

The following components are required to build a complete 16 MiB image:

```{eval-rst}
+--------------------+-----------------------------------------+--------------------------------+
| Component          | Source                                  | Destination                    |
+====================+=========================================+================================+
| IFD                | The board's own verified SPI dump       | ``descriptor.bin``             |
+--------------------+-----------------------------------------+--------------------------------+
| Intel CSME         | The board's own verified SPI dump       | ``me.bin``                     |
+--------------------+-----------------------------------------+--------------------------------+
| EC firmware        | The board's own verified SPI dump       | ``ec.bin``                     |
+--------------------+-----------------------------------------+--------------------------------+
| Discrete GPU VBIOS | OEM UEFI volume (optional for UMA)      | ``pci10de,1d12.rom``           |
+--------------------+-----------------------------------------+--------------------------------+
| VBT                | Distributed with the mainboard source   | ``src/mainboard/xiaomi/``      |
|                    |                                         | ``tm1703/data.vbt``            |
+--------------------+-----------------------------------------+--------------------------------+
| FSP-M and FSP-S    | Kaby Lake package from ``3rdparty/fsp`` | Added automatically            |
+--------------------+-----------------------------------------+--------------------------------+
| CPU microcode      | ``3rdparty/intel-microcode``            | Added automatically            |
+--------------------+-----------------------------------------+--------------------------------+
```

### Extracting flash components

Extract the IFD and CSME regions from a verified 16 MiB dump of the machine using coreboot's `ifdtool`:

```sh
coreboot_dir=$PWD
dump=$(realpath /path/to/tm1703-16mib.bin)
blob_dir=3rdparty/blobs/mainboard/xiaomi/tm1703
extract_dir=$(mktemp -d)

test "$(stat -c %s "$dump")" -eq 16777216
mkdir -p "$blob_dir"
make -C util/ifdtool

(cd "$extract_dir" && \
	"$coreboot_dir/util/ifdtool/ifdtool" -x -p sklkbl "$dump")
install -m 0644 "$extract_dir/flashregion_0_flashdescriptor.bin" \
	"$blob_dir/descriptor.bin"
install -m 0644 "$extract_dir/flashregion_2_intel_me.bin" \
	"$blob_dir/me.bin"
```

The EC image occupies a board-specific range outside the descriptor's EC region, so extract it separately:

```sh
dd if="$dump" of="$blob_dir/ec.bin" \
	bs=1 skip=$((0x900000)) count=$((0x040000)) status=none
```

### Extracting NVIDIA MX150 VBIOS

For models with discrete NVIDIA graphics (SKU 1 and SKU 2), the GP108 VGA BIOS can be extracted from the OEM UEFI firmware image using [UEFITool / UEFIExtract](https://github.com/LongSoft/UEFITool/releases):

1. Unpack the OEM firmware dump using `uefiextract`:
   ```sh
   uefiextract "$dump"
   ```
2. Locate the raw section corresponding to FFS GUID `E35B2FEA-017C-47E8-AF17-C38CA2ED1F8B`.
3. Copy the 180,224-byte raw section into the blob directory:
   ```sh
   install -m 0644 path/to/section_raw.bin "$blob_dir/pci10de,1d12.rom"
   ```

For UMA-only configurations (SKU 3), this file is not required.

### Flash layout

```text
0x000000..0x000fff  Intel Flash Descriptor
0x001000..0x8fffff  Intel CSME (ME)
0x900000..0x93ffff  EC firmware
0x940000..0xffffff  BIOS region, including coreboot
```

Unlike many laptops, the EC firmware used by this port is part of the main
16 MiB SPI image at offset `0x900000`.

## Building coreboot

Select `Xiaomi` as the mainboard vendor and `Mi Notebook Air 13.3" (TM1703)`
as the mainboard model, then build coreboot normally:

```sh
make menuconfig
make
```

The resulting `build/coreboot.rom` is a complete 16 MiB image. When `pci10de,1d12.rom`
is present in the blob directory, the build system automatically includes it in CBFS
and generates the ACPI `_ROM` method for `\_SB.PCI0.RP01.PXSX`.

## Flashing

### External programming

Use an external 3.3 V SPI programmer and an SOIC-8 clip:

1. Shut the machine down and disconnect the charger.
2. Remove the bottom cover and disconnect the main battery.
3. Read the 16 MiB flash at least twice and compare the dumps before writing.
4. Program the complete `build/coreboot.rom` and run the programmer's verify
   operation.
5. Remove the clip before reconnecting the battery and powering the board.

The SPI flash device on the development hardware is a Winbond W25Q128.V with
JEDEC ID `0xef4018`.

*Note:* The factory CSME firmware is in Manufacturing Mode. It is recommended
to preserve the original dump and not close Manufacturing Mode during development.

After complete power loss (G3), both the vendor firmware and coreboot perform
two platform resets before the successful boot. A subsequent boot from S5,
without removing power, should not reset.

### Internal programming

Internal flashing from within the running operating system has not been validated
and is planned for later development stages. Use an external SPI programmer.

# Xiaomi Mi Notebook Air 13.3-inch (TM1703)

This page describes the coreboot port for the 2018 Xiaomi Mi Notebook Air
13.3-inch, board model TM1703. The port is still under development and should
not yet be considered suitable for daily use.

## Hardware

```{eval-rst}
+------------------+------------------------------------------------------+
| CPU              | Intel Core i5-8250U (Kaby Lake-R)                    |
+------------------+------------------------------------------------------+
| PCH              | Intel Sunrise Point-LP                               |
+------------------+------------------------------------------------------+
| Integrated GPU   | Intel UHD Graphics 620 (8086:5917)                   |
+------------------+------------------------------------------------------+
| Discrete GPU     | NVIDIA GeForce MX150, GP108M (10de:1d12)             |
+------------------+------------------------------------------------------+
| Memory           | Soldered DDR4, selected by board straps              |
+------------------+------------------------------------------------------+
| EC               | Nuvoton NPCE family                                  |
+------------------+------------------------------------------------------+
| Coprocessor      | Intel CSME 11.8                                      |
+------------------+------------------------------------------------------+
| SPI flash        | Winbond W25Q128.V, 16 MiB, SOIC-8                    |
+------------------+------------------------------------------------------+
```

The board has no SO-DIMM socket. Different memory-down configurations are
selected using the `GPP_D0..D3` straps, and their SPD data is stored in CBFS.

## Required firmware components

The following components are required to build a complete image:

```{eval-rst}
+-----------------+-----------------------------------------+--------------------------------+
| Component       | Source                                  | Destination                    |
+=================+=========================================+================================+
| IFD             | The board's own verified SPI dump       | ``descriptor.bin``             |
+-----------------+-----------------------------------------+--------------------------------+
| Intel ME        | The board's own verified SPI dump       | ``me.bin``                     |
+-----------------+-----------------------------------------+--------------------------------+
| EC firmware     | The board's own verified SPI dump       | ``ec.bin``                     |
+-----------------+-----------------------------------------+--------------------------------+
| VBT             | Distributed with the mainboard source   | ``src/mainboard/xiaomi/``      |
|                 |                                         | ``tm1703/data.vbt``            |
+-----------------+-----------------------------------------+--------------------------------+
| FSP-M and FSP-S | Kaby Lake package from ``3rdparty/fsp`` | Added automatically            |
+-----------------+-----------------------------------------+--------------------------------+
| CPU microcode   | ``3rdparty/intel-microcode``            | Added automatically            |
+-----------------+-----------------------------------------+--------------------------------+
```

The IFD, ME, and EC firmware are not distributed with coreboot. Extract the IFD
and ME regions from a verified 16 MiB dump of the same machine using coreboot's
`ifdtool`. Unlike fixed-offset extraction, `ifdtool` reads the region layout
from the flash descriptor.

```sh
coreboot_dir=$PWD
dump=$(realpath /path/to/tm1703-16mib.bin)
blob_dir=3rdparty/blobs/mainboard/xiaomi/tm1703
extract_dir=$(mktemp -d)

test "$(stat -c %s "$dump")" -eq 16777216
mkdir -p "$blob_dir"
make -C util/ifdtool

(cd "$extract_dir" && \
	"$coreboot_dir/util/ifdtool/ifdtool" -x -p sklkbl "$dump")
install -m 0644 "$extract_dir/flashregion_0_flashdescriptor.bin" \
	"$blob_dir/descriptor.bin"
install -m 0644 "$extract_dir/flashregion_2_intel_me.bin" \
	"$blob_dir/me.bin"
```

The EC image occupies a board-specific range outside the descriptor's EC
region, so extract it separately:

```sh
dd if="$dump" of="$blob_dir/ec.bin" \
	bs=1 skip=$((0x900000)) count=$((0x040000)) status=none
```

The image layout is:

```text
0x000000..0x000fff  Intel Flash Descriptor
0x001000..0x8fffff  Intel ME
0x900000..0x93ffff  EC firmware
0x940000..0xffffff  BIOS region, including coreboot
```

Unlike many laptops, the EC firmware used by this port is part of the main
16 MiB SPI image at offset `0x900000`.

## Building

Select `Xiaomi` as the mainboard vendor and `Mi Notebook Air 13.3" (TM1703)`
as the mainboard model, then build coreboot normally:

```sh
make menuconfig
make
```

The resulting `build/coreboot.rom` is a complete 16 MiB image. Verify its FMAP
layout and the IFD, ME, and EC regions before programming it.

The integrated display is initialized with libgfxinit and the board VBT. An
Intel or NVIDIA VGA Option ROM is not required for the current coreinfo
bring-up payload.

## Intel Management Engine and Boot Guard

The test hardware uses Intel CSME firmware 11.8.50.3470. Its factory state has
Manufacturing Mode enabled and the Field Programmable Fuses are not committed.

```{warning}
Do not run Intel firmware-update or ME provisioning tools, and never issue the
`CLOSEMNF` command. Closing Manufacturing Mode may irreversibly program Boot
Guard policy into FPFs and prevent unsigned coreboot images from booting. A
backup of the SPI flash cannot undo programmed FPFs.
```

Preserve the IFD and ME regions from the machine's own dump. The port uses the
normal BIOS-to-ME initialization messages required by Intel reference code; it
does not require closing Manufacturing Mode.

## Flashing

### Internal programming

Internal programming has not been validated and is not used during bring-up.
Do not use `flashrom -p internal` on this port.

### External programming

Use an external 3.3 V SPI programmer and an SOIC-8 clip:

1. Shut the machine down and disconnect the charger.
2. Remove the bottom cover and disconnect the main battery.
3. Read the 16 MiB flash at least twice and compare the dumps before writing.
4. Program the complete `build/coreboot.rom` and run the programmer's verify
   operation.
5. Remove the clip before reconnecting the battery and powering the board.

Select the programmer definition matching the actual flash marking. The board
used for development contains a Winbond W25Q128.V device with JEDEC ID
`0xef4018`.

After complete power loss (G3), both the vendor firmware and coreboot perform
two platform resets before the successful boot. A subsequent boot from S5,
without removing power, should not reset.

## Bring-up status

### Confirmed

- FSP-M memory initialization with the tested soldered DDR4 configuration
- Native coreboot multiprocessor initialization on all CPU threads
- Intel UHD 620 display initialization with libgfxinit
- Internal display and keyboard operation in coreinfo
- Enumeration of the NVIDIA MX150, Intel Wireless 8265, and NVMe SSD
- CSME initialization, including DRAM Init Done and End of Post
- SPI flash console for early bring-up diagnostics

### Not working or not yet tested

- Booting an operating system or payloads other than coreinfo
- Complete GPIO, interrupt, wake, and power-management configuration
- EC events, battery reporting, lid switch, and ACPI power-button handling
- Touchpad and the Serial IO I2C controllers
- Runtime power management and graphics operation of the NVIDIA GPU
- Internal audio, headset detection, camera, and microphone
- External HDMI and USB-C DisplayPort output
- USB-C/UCSI functionality
- S3 suspend and resume
- Internal firmware programming

The status above describes the bring-up branch and should be updated as each
subsystem is tested on hardware.
